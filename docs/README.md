# Развёртывание на Beget

В `.vscode/sftp.json` путь назначения — `/aiworkr1.beget.tech/public_html`.
Загрузите содержимое корня проекта в этот каталог, сохранив структуру:

```text
public_html/
  .htaccess
  index.php
  app/Controllers/HomeController.php
  config/db.php                    (создаётся отдельно при настройке MySQL)
  public/
    .htaccess
    index.php
    css/
    js/
  views/home.php
```

Корневой `index.php` запускает `public/index.php`. Корневой `.htaccess`
закрывает HTTP-доступ к конфигурации и внутренним каталогам приложения.
Обязательно загрузите оба файла, включая скрытый `.htaccess`.
Не загружайте `.git`, `.vscode`, документацию и локальные секреты.
`uploadOnSave` выключен: сохранения файла недостаточно, нужна ручная загрузка
изменённых файлов через FTP. Не используйте синхронизацию с удалением файлов:
на сервере может быть свой `config/db.php`.

## Проверка ошибки 403

1. В панели Beget откройте «Сайты» → файлы нужного домена. Убедитесь, что
   `index.php` и `.htaccess` — файлы непосредственно в `public_html`, а не в
   дополнительном каталоге проекта. `.htaccess` не должен быть папкой.
2. Проверьте права чтения: обычно для каталогов используют 755, для файлов 644.
3. Выберите PHP 8.2 или новее. Откройте `/` и `/index.php`: должна появиться
   диагностическая страница. Без `config/db.php` она сообщает, что БД не настроена.
4. Проверьте `/config/db.example.php`, `/views/home.php`, `/.git/config` и
   `/.vscode/sftp.json`: ожидается отказ 403, без содержимого файлов.
5. Если 403 сохраняется, проверьте привязку домена к каталогу и журнал ошибок
   Apache в панели Beget. Локальный код не позволяет определить права и настройки
   виртуального хоста на сервере.

Ранее `public/index.php` содержал пробелы перед `<?php`. Это нарушало требование
`declare(strict_types=1)` быть первой инструкцией и могло приводить к ошибке 500
после устранения 403. Файл должен начинаться с `<?php`, без BOM и пробелов.

## Альтернативная схема

Если хостинг позволяет назначить корнем сайта каталог `public`, храните `app`,
`config` и `views` рядом с ним вне HTTP-корня. Тогда входной точкой будет
`public/index.php`; корневой адаптер не используется. Не загружайте только
содержимое `public` без остальных каталогов: нужны контроллер и шаблон.

## Локальная проверка

При установленном PHP 8.2+ выполните из корня проекта:

```powershell
Get-ChildItem -Recurse -Filter *.php | ForEach-Object { php -l $_.FullName }
php -S 127.0.0.1:8080 -t public
```

Откройте `http://127.0.0.1:8080/`. Встроенный сервер PHP не читает `.htaccess`;
правила доступа необходимо проверять на Apache/Beget.
